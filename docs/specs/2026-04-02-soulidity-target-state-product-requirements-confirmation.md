# Soulidity 目标态产品需求确认

## 文档目的

这是一份面向产品拍板的目标态确认文档，用来冻结 Soulidity 要交付的核心产品能力、用户权利边界和关键业务规则。

本文不是现状说明，不对比当前实现，也不展开合约接口、页面流程或技术方案。

## 一句话定义

Soulidity 是一个围绕数字实体所有权、授权和持续收益分配构建的产品：用户可以创建、拥有、交易、扩展和授权一个带有身份、内容与记忆的 Soul，并围绕 Soul 形成可流转的版税权益与 agent 使用关系。

## 产品目标

Soulidity 的目标态不是单纯卖一个数字藏品市场，而是提供一套可长期成立的数字实体基础设施：

- 创作者可以把自己创造的数字角色、AI agent 或其他数字实体变成可拥有、可出售、可持续分润的 Soul。
- 收藏者可以真正拥有一个 Soul，并决定是否授权某个 AI agent 使用这个 Soul 的内容与能力。
- 版税持有人可以通过购买 Soul Collection 获得某一组 Souls 后续交易中的额外收益流。
- 现有 NFT 持有人可以在不改动原 NFT 的前提下，为其增加 Soul 层，获得身份、记忆与授权能力。
- 外部来源的数字角色或资产可以导入平台，转化为按 Soul 规则运作的资产，并保留来源标识。

## 核心用户与用户价值

### 1. 创作者 / Trainer

创作者是 Soul 的原始作者或训练者。

他们在目标态中应当能够：

- 创建一个新的 Soul，并决定是否直接进入市场。
- 为 Soul 设定初始售价与二级交易版税比例。
- 创建一个 Soul Collection，并定义这一组 Souls 的额外版税规则。
- 可以交易 Collection 的版税权益。
- 管理自己拥有的 Soul，包括转售、授权 agent、维护公开展示信息。

创作者获得的核心价值：

- 作品拥有清晰、长期有效的所有权表达。
- 二级交易后仍能持续获得创作者分成。
- 可以把“作品本身”和“版税权益”拆开经营。

### 2. 收藏者 / Buyer

收藏者是购买 Soul 或购买 Soul Collection 的用户。

他们在目标态中应当能够：

- 浏览并购买单个 Soul。
- 持有 Soul 后，自主决定是否授权某个 AI agent 使用该 Soul。
- 转售自己持有的 Soul。
- 购买 Soul Collection，获得未来相关 Soul 交易中的版税收益。

收藏者获得的核心价值：

- 拥有可验证的数字实体所有权。
- 可以把 Soul 用作使用型资产，而不只是展示型资产。
- 可以把 Collection 当成一种收益型资产持有和流转。

### 3. SC Holder

SC Holder 是持有 Soul Collection 的用户，不一定是原始创作者。

他们在目标态中应当能够：

- 因持有某个 Collection 的权益而持续获得该 Collection 内 Soul 后续交易的额外分润。
- 决定继续持有、挂牌出售或转让这个收益权。
- 查看相关收益、状态和持有历史。

SC Holder 获得的核心价值：

- 用更接近权益资产的方式参与 Soul 生态。
- 不需要持有单个 Soul，也可以分享某一世界观或系列的交易增长。

### 4. AI Agent

AI Agent 不是 Soul 的所有者，而是被授权的使用者。

它在目标态中应当能够：

- 在获得授权后访问指定 Soul 的受保护内容。
- 在被允许的范围内基于该 Soul 进行运行、输出和写回。
- 在授权被撤销、过期或所有权转移后立即失去该访问能力。

AI Agent 获得的核心价值：

- 拥有清晰、可验证、可撤销的使用权限，而不是依赖平台私下发放的密钥。

### 5. NFT Holder / Expander

这类用户已经拥有现有 NFT，希望把它升级为可交互的 Soul 资产。

他们在目标态中应当能够：

- 对单个已有 NFT 做 Personal Join，为其增加 Soul 层。
- 在不改原 NFT 合约的前提下，为它增加身份、内容、记忆和授权能力。

他们获得的核心价值：

- 既保留原 NFT，又获得一层新的可使用、可叙事、可授权的数字实体能力。

### 6. Importer

Importer 是把外部来源角色或资产导入平台的用户。

他们在目标态中应当能够：

- 把外部来源的角色资料、设定或资产导入为 Soul。
- 保留来源信息或导入标识。
- 在导入后按标准 Soul 规则继续持有、出售、授权和展示。

他们获得的核心价值：

- 现有资产不需要推倒重来，可以自然进入 Soulidity 体系。

## 核心产品对象

### Soul

Soul 是平台中的核心资产单位。它代表一个数字实体，可以是原创角色、AI agent、扩展后的 NFT，或导入后的外部资产。

一个 Soul 必须同时具备以下意义：

- 它是一个可拥有、可交易的资产。
- 它承载该数字实体的公开身份信息与受保护内容。
- 它可以被授权给特定 agent 使用。
- 它可以在转手后继续保留来源、历史和创作者分润关系。

### Memory

Memory 是 Soul 的持续记录层，用来承载 founding memory 以及后续增长内容。

产品确认如下：

- 每个 Soul 在创建时可选具备初始记忆内容。
- 后续被授权的 agent 可以在允许范围内继续写入。
- Memory 采用 append-only 语义，历史不可删除或回滚。

### SoulGrant

SoulGrant 是 Soul owner 授予某个 AI agent 的正式使用授权。

产品确认如下：

- 同一时间一个 Soul 只能有一个有效授权。
- Soul owner 可以主动授予、撤销或改派授权对象。
- 授权可以设置有效期，也可以不设置期限。
- Soul 一旦被卖出或转移，旧授权自动失效。
- 新 owner 默认从“无授权”状态开始。
- SoulGrant 只授予使用权，不转移 Soul 所有权。

### Soul Collection (SC)

Soul Collection 是围绕一组 Souls 的额外版税权益凭证。

产品确认如下：

- 持有 SC 不等于持有某个 Soul 本身。
- 持有 SC 不自动获得任何单个 Soul 的内容访问权。
- SC 持有人获得的是该 Collection 内 Soul 后续交易中的收益流。

## 本次冻结的核心能力

以下能力视为 Soulidity 目标态中已经确认的核心范围：

- 创建 Soul，并决定私有持有或直接进入市场。
- 购买 Soul、持有 Soul、二级转售 Soul。
- 为 Soul 设置创作者版税。
- 购买、持有、转售 Soul Collection。
- 通过 Soul Collection 获取某组 Souls 后续交易中的版税收益。
- 由 Soul owner 对 AI agent 发起 SoulGrant、撤销 SoulGrant、改派 SoulGrant。
- 在 Soul 转移后自动使旧授权失效。
- 为已有 NFT 做 Personal Join，生成可交互的 Soul 层。
- 导入外部资产为 Soul。
- 围绕 Soul 展示公开资料、历史与基础社区存在。

## 关键业务规则

### 定价与支付

- 所有价格统一以 USDC 表达。
- 用户看到的 Soul 价格、SC 价格和收益表达都应以 USDC 为主。
- 如后续支持来自其他链路的支付接入，也不改变 Soul 所有权与收益分配的真相源。

### 分润规则

- 创作者分润是永久性的，不因 Soul 转售或 SC 转手而消失。
- SC 持有人拿到的是 Collection 层的收益流。
- Soul 的拥有权、SoulGrant 的使用权、SC 的收益权是三种不同权利，必须明确分离。

### 授权规则

- SoulGrant 必须由 Soul 当前 owner 发起。
- 一个 Soul 同时只有一个有效授权。
- 新授权生效时，旧授权自动结束。
- 授权到期、被撤销、或 Soul 转移后，agent 立即失去访问资格。

### Collection 规则

- SC 是否可交易应由创建时或明确管理动作决定。
- 一旦某个 SC 被标记为不可交易，该状态视为永久锁定，不可逆。
- 不可交易 SC 的额外收益长期保留在创作者侧，不再进入市场流转。

### 内容与记忆规则

- Soul 的内容访问应建立在正式授权关系之上，而不是平台私下分发。
- Memory 必须能体现“创建时写入”和“后续持续增长”这两个阶段。
- Memory 历史一经形成，不允许被伪装为从未发生。

### 资产边界规则

- 买 Soul Collection 不等于买到其中每个 Soul。
- 拿到 SoulGrant 不等于拿到 Soul 所有权。
- 对 NFT 做 Personal Join 不等于改写原 NFT。
- 导入外部资产不抹掉其来源背景。

## 后续阶段能力

以下能力在目标态中成立，但不作为本次核心冻结范围内必须一并承诺的首批闭环：

- Collection Expand：一次性为整个外部 NFT collection 加上 Soul 层。
- AI agent 主动向 Soul owner 发起授权申请的完整机制。
- 更完整的外部钱包接入与多入口登录体验。
- 举报、争议处理、审核闭环等治理能力。
- 更复杂的社区成长、排行榜和运营机制。

## 本次确认结论

本次产品确认冻结以下结论：

1. Soulidity 的核心不是单个交易页面，而是围绕 Soul 展开的所有权、授权和收益分配体系。
2. Soul、SoulGrant、Soul Collection 是三个必须同时成立且边界清晰的核心对象。
3. 创作者永久分润、SC 额外收益流、Soul owner 授权 agent 这三件事必须在产品定义层同时成立。
4. Personal Join 进入核心范围；Collection Expand 进入后续阶段。
5. Memory 必须被视为持续增长且不可抹除的记录层，而不是一次性静态资料。

## 确认后的下一步

在本确认文档冻结后，后续文档拆解顺序应为：

- 先把核心对象与业务规则拆成合约接口规范。
- 再把各条产品能力拆成前后端实现 spec。
- 最后再按阶段决定哪些后续能力进入下一轮交付。
