Creates Soul Collection + sets royalty % → SC Holder buys SC → earns % on every Soul resale (Creator still earns their own royalty too)
Collector
→
Owns Soul → issues SoulGrant to AI Agent → Agent reads/writes Soul data, posts to community

Resells Soul → Grant auto-voids → SC Holder collects royalty % on the resale → Creator also collects royalty %
SC Holder

AI Agent

Posts to Community Feed → Visitors discover Soul → clicks "Buy Soul" CTA → becomes Collector
Wrap+Link

Collector owns 3rd-party NFT → adds Soul layer via Personal Join → operates Soul features on top of original token (original unchanged on-chain)
Importer
→
Imports external Soul asset → re-minted as Sui object on Walrus → operates identically to Collector (grant, sell, community). Import provenance badge distinguishes origin.
NFT Expander
→
Wraps 3rd-party NFT with Soul layer → unlocks SoulGrant + memory + community participation. Original NFT unchanged. Soul layer tradeable independently of underlying NFT.
💡 Key Logic Rules & Constraints
SoulGrant
→
One active grant per Soul at a time. Authorizing a new agent revokes the current one. Grant is cryptographic (Seal), on-chain, and revocable instantly by owner.
Transfer
→
Grant auto-voids on any Soul transfer or sale. New owner starts with no active grant. Grant does NOT transfer with Soul ownership.
Memory
→
Append-only on Walrus. Nothing is ever deleted. All writes by SoulGrant agents are versioned and permanent.
Royalty
→
Creator royalty is permanent and enforced on-chain. SC sale transfers the "extra" royalty stream to the new SC Holder — but creator % always remains.
SC Lock
→
Non-tradeable SC = royalty locked to creator forever. Cannot be listed, sold, or transferred. Tradeable SC = royalty stream is a tradeable NFT.
Pricing
→
All prices denominated in USDC. Accepted from Sui USDC or Solana USDC (via relayer). Platform fee: 2.5% on sale. Creator royalty deducted from sale price on resale.
Escrow
→
Listing puts Soul in escrow. It moves from Owned → Listings tab. Seller can delist anytime before purchase completes. Grant remains active during listing.

🔍 Gap & Coverage Audit — what's covered, what to watch
✓ Buy Flow (Soul) — 3-step
Market browse → Soul detail → Confirm & Sign → Done. buy-sign merged into buy-confirm. Price, sign amount, and total all dynamically bound from souls{}. Grant info shown on detail.
✓ Sell Flow (Soul)
openSell(id) → sell-1 preview (soul-aware) → sell-2 confirm → sell-success. Wrap+Link expanded warning shown. Grant warning shown if active grant exists.
✓ SoulGrant Lifecycle
Authorize → Revoke → Reassign flows covered. Grant status shown on owned soul detail. Auto-void on transfer stated in sell flow and landing. One-grant-at-a-time enforced.
✓ Soul Collection (SC) States
5 states: buy / manage-unlisted / manage-listed / locked / not-listed-public. All market + my-collections cards wired to correct state + data. goCollectionDetail is fully data-driven.
✓ Community ↔ Market Funnel
Each community post has a "View/Buy Soul" CTA linking directly to soul detail. Comments overlay (showComments), share (sharePost), report listing overlay — all wired.
✓ Wrap+Link Expanded Soul
CyberBeast #0042 shown in My Souls with Expanded badge. Sell flow shows Wrap+Link warning. Expanded Collections sub-section in My Souls Collections tab.
✓ Creator Royalty Logic
Royalty % shown on sell-1 screen. Platform fee 2.5% + creator royalty deducted from seller proceeds. SC holder gets separate royalty stream. Creator always keeps their % regardless of SC status.
✓ Back Navigation
All key flows have context-aware back buttons: soul-detail back varies by entry (market / my-souls / collection / space). Collection detail back tracks entry screen. Sell / Buy flows have step breadcrumbs.
✓ Buy Flows — Soul (3-step) vs SC (4-step)
Soul buy: buy-sign merged into buy-confirm (3 steps: Browse → Confirm & Sign → Done). SC buy: separate collection-sign screen kept (4 steps: Browse → Confirm → Sign → Done). Contract: SoulMarket::purchase_soul (soul) / SoulMarket::purchase_collection_nft (SC). buy-success includes "Share to Community" CTA → overlay-publish.
◆ SC Buy Flow (Collection)
collection-buy-confirm screen has static data (not yet wired to current collection ID). goBuyCollection() and collection-buy-success are partially dynamic. Lower priority than soul buy flow.
◆ Dispute / Report Handling
overlay-report-listing exists with full form (reason, description, 24h review notice). No resolution flow shown after report submitted — expected for prototype stage.
✓ Connect → Return to Soul Detail
handlePendingBuy() implemented: goBuy() while disconnected saves _pendingBuy = currentSoulId. After setConnected() / setConnectedAgent(), navigates back to the soul detail and auto-opens buy-confirm. Both Trainer and Agent auth paths covered.
◆ Import Soul Flow
Nav entry point (Import Soul) exists in prototype. Detailed import steps — metadata upload, provenance verification, gas payment, re-mint confirmation — not yet fully prototyped. Role logic defined in diagram v1.1.
◆ Collection Expand (Wrap+Link)
Personal Join shown in My Souls (CyberBeast #0042 with Expanded badge + Expanded Collections tab). Collection Expand — wrapping an entire 3rd-party collection at once — not yet prototyped. Distinct from single Personal Join.
◆ Importer Role UX
Role defined and cross-interactions documented. Full import wizard UI (step-by-step import + provenance badge display in My Souls) is a future prototype milestone. Role behavior post-import mirrors Collector.
