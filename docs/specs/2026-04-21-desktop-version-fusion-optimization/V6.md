## Step 1：分析 4 个版本（融合输入）

- V1（体验优先）：用户感知强，但稳定性不足。
- V2（工程稳定）：可靠性最好，但缺少吸引力。
- V3（能力扩展）：任务覆盖面广，但有信任风险。
- V4（主动智能）：启动成本低，但打扰风险高。

## Step 2：决策

选 V2 作为骨架；吸收 V1 的存在感、V3 的轻闭环能力、V4 的温和主动。
原则：**稳定优先，能力增量必须可控、可回滚**。

## Step 3：融合优化

- P0：auth/link 稳定性收口（防误判绑定态）
- P0：生命感最小闭环（低打扰默认）
- P1：quick capture + 轻待办 + 审批闭环

每项都绑定：owner、文件面、验收条目、回滚说明。

## Step 4：最终版本（完整代码）

最终版本代码已落库在：
- `desktop/packages/shared/src/plans/desktop-improvement-v6.ts`

其能力包括：
- 严格类型定义（priority / owner / milestone / acceptance / rollback）
- 3 个里程碑（2 个 P0 + 1 个 P1）
- 文件级 target mapping，可直接驱动实施排期

## Step 5：自我验证

- 覆盖 plan 结构完整性（版本、里程碑、验收、回滚）
- 覆盖依赖关系合法性（dependsOn 必须存在）
- 覆盖 targetFiles 必须存在（防“写了不存在的实施路径”）

## Step 6：自动验证

运行：

```bash
npm run validate:v6-plan
```

通过条件：
- `v6.plan.json` 与 TS 计划一致（防双轨漂移）
- 必要章节存在
- `v6.plan.json` 结构合法
- `dependsOn` 无自依赖、无环依赖、无悬空依赖
- `targetFiles` 全部真实存在
