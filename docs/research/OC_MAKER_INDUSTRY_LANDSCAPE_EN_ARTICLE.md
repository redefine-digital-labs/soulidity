# OC / Character Maker Industry: Product-First Industry Map (English)

## Executive summary (for people who only have 3 minutes)

The OC/Character ecosystem is **not one product category**.  
It is a set of adjacent sub-markets around one shared object: the character.

- making the character (Maker)
- storing and evolving the character (Archive/World)
- showing and socializing the character (Community/RP/Event)
- commissioning / trading / adoptable workflows
- running the character in Avatar, game, stream, or AI runtime

These are solved by **different products**, often by different teams, with different payment logic.

So the real unit is **solution chains**, not one monolithic "Character Maker app".

## 1) How I define this industry in this study

This is a product-level map, not a company-level due diligence.  
The report is based on public information as of **2026-08-12** and intentionally excludes:

- market size predictions not supported by verified cohorts
- any single-company strategy assumptions
- deep Web3/Agent positioning as "core OC product"

## 2) Three-layer model

1. **Core OC solutions**
   - Character Makers
   - OC archive / world / profile systems
   - OC social + RP + events
   - commissions, YCH, adoptable transfer and license workflows

2. **Adjacent extensions**
   - Avatar and virtual world ecosystems
   - worldbuilding/writing SaaS
   - 2D/3D model asset chains
   - AI character / chat companions

3. **Infrastructure (far-neighbor)**
   - Payments, escrow, refunds, disputes
   - rights/provenance/permission layers
   - agent runtime and external workflow tooling

This helps prevent category confusion:  
**Toyhouse is a core archive/society layer**,  
**ZEPETO/VRoid are runtime/asset layers**,  
**Daydreams/Virtuals are far-neighbor infra**, not core.

## 3) What users actually solve (five tasks)

### Task A: Visual creation

Users need fast creation of recognizable characters.

Main solutions:
- UGC Makers (e.g., Picrew-style ecosystems)
- Fixed-asset dressing
- AI generation
- 3D/custom model editors

**Status:** highly mature; breadth is high.

### Task B: Organization and continuity

Users need to keep identity, history, relationships, and lore coherent.

Main solutions:
- Archive platforms
- Worldbuilding SaaS
- community profile systems

**Status:** mature in some products, fragmented overall.  
Import/export and continuity across products are uneven.

### Task C: Display and social interaction

Users need visibility, feedback, roleplay and rituals.

Main solutions:
- Feed / profile feeds
- RP worlds and forums
- event systems (battle/season systems, weekly formats)

**Status:** feature-rich, but network effects and discovery mechanics are still inconsistent across tools.

### Task D: Commissioning and trading

Users buy/sell design and character rights.

Main solutions:
- commission tools and marketplaces
- YCH/adoptable flow
- transfer + ownership logging

**Status:** practical infrastructure exists (payment, reputation, transfer, auction), but rights/ownership semantics remain informal in practice.

### Task E: Runtime usage

Users want the character to exist beyond static profile pages.

Main solutions:
- Avatar ecosystems (dress/props/worlds)
- AI characters and companions
- Agent-like interaction systems

**Status:** active, still divergent in standards and licensing assumptions.

## 4) Regional topology (why this matters)

- **Mainland China**
  - Strong mobile orientation
  - Faster convergence between “maker + archive + chat + commission”
  - Bigger emphasis on nurturing OC identities and interaction governance

- **Japan**
  - Strong open maker / Avatar culture
  - Mature avatar consumption and creator permission habits

- **Korea**
  - Industrialized fixed-asset dressing and scalable mobile operations
  - strong avatar and social loops with global distribution traits

- **English internet / North America**
  - stronger archive + adoptable + commission norms
  - stricter AI-free positioning in some core communities

> These are profile-level observations from visible public samples, not exhaustive global proofs.

---

## 5) What is already working well

1. **Maker creation is highly accessible.**  
   Users can create characters in many forms and formats.

2. **Archive+social combinations are viable.**  
   Many users already combine multiple products to build a full life cycle.

3. **Commission/adoptable mechanics already exist.**  
   There is real trade behavior with platform-specific norms.

4. **Avatar/AI runtimes create new value surfaces.**  
   Characters are no longer only images; they become entities in live/social/interactive contexts.

---

## 6) What is still fragmented

- Identity/principal roles are not unified (`creator / designer / owner / licensee` semantics differ by platform).
- Permission design is fragmented (modification, commercial use, resale, merchandise, AI usage rules).
- Shared character identifiers across tools are weak.
- Data portability and recovery (migration, backup, exit) is inconsistent.
- Governance costs are rising with minors, identity, payment trust, and emotional interaction.

---

## 7) Practical conclusion

From a market perspective, this is **a modular stack, not a monolith**.

The near-term opportunity is less “build one more maker” and more:

- higher-quality **cross-layer interoperability**
- cleaner **rights/licensing workflows**
- stronger **portable identity + provenance**
- safer **payment/dispute** rails

If you’re building in this space, the moat is not the character sprite itself.
The moat is **workflow integrity across creation, archive, social, commission, and runtime**.
