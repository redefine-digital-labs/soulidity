# Pixel Newsroom — /pipeline 重设计方案

## 概念

俯瞰视角像素风格新闻编辑室，用 PixiJS 渲染。用户可实时观看 OpenClaw AI 角色在流水线上处理新闻的全过程，管理员可手动干预。

核心体验：**看新闻从收件篮 → 流水线加工 → 信鸽送出** 的完整视觉旅程。

### 视觉元素

| 元素 | 说明 |
|------|------|
| **房间** | 像素地板砖 + 墙壁纹理，温暖灯光氛围 |
| **收件篮** | 左侧像素邮箱/文件篮，新闻多时视觉堆高，数量角标动态变化 |
| **工位** | 每个角色有专属小桌子/工作台，角色站在旁边 |
| **传送轨道** | 工位间有地面轨道连接，新闻卷轴沿轨道移动 |
| **窗户** | 右上角开窗，光线投射效果，信鸽从此飞出 |

- 设计尺寸 1200x700，等比缩放适配屏幕
- 最多 3 条流水线纵向堆叠，间距足够容纳角色 sprite
- 固定场景，不滚动

## 流水线机制

### 模式：混合（自动 + 管理员干预）

- **自动模式**：流水线自动跑，新闻按评分优先级自动从 pending 池进入空闲流水线
- **管理员干预**：管理员可手动选新闻、开关流水线、重试失败、跳过步骤

### 流水线规格

- 默认 1 条流水线
- 管理员可按需新开，最多 3 条
- 每条流水线 5 个工位，对应 5 个角色
- 新闻以"像素卷轴"形态在工位间传递

### 流程

```
收件篮(pending) → 卷轴弹出 → Scout工位 → Scribe工位 → Seer工位 → Smith工位 → Herald工位 → 信鸽飞出窗户(published)
```

## 角色动画系统

### 5 个 OpenClaw 角色 × 4 种动画状态

| 角色 | Idle 待机 | Working 工作 | Done 完成 | Failed 失败 |
|------|----------|-------------|----------|------------|
| **TIDE SCOUT** | 举望远镜左右张望 | 望远镜聚焦闪光，扫描线扫过 | 放下望远镜点头 | 望远镜碎裂 |
| **SHELL SCRIBE** | 拿着羽毛笔 idle 晃 | 奋笔疾书，墨水飞溅粒子 | 举起稿件挥手 | 稿纸揉成团 |
| **REEF SEER** | 水晶球微光浮动 | 水晶球高速旋转发光，数据符号粒子 | 水晶球爆发光环 | 水晶球变暗碎裂 |
| **CLAW SMITH** | 锤子搁在肩上 | 挥锤敲打，火花粒子飞溅 | 举锤庆祝 | 锤子掉落 |
| **HARBOR HERALD** | 号角放在腰间 | 举起号角吹响，音符粒子 | 吹出最终号声，信鸽起飞 | 号角卡住冒烟 |

### 动画实现

- 每个角色一张 sprite sheet，4 状态 × 4-6 帧
- CSS steps() 风格逐帧播放，通过 PixiJS AnimatedSprite 实现
- 专属粒子效果：墨水、火花、光粒子、音符等

### 新闻卷轴动画

- 从收件篮取出时弹出动画
- 沿流水线轨道在工位间滑动（缓动曲线）
- 到达工位时停下，角色开始处理
- 处理完后卷轴短暂发光，滑向下一站
- 最终站完成后卷轴变成信鸽飞向窗户

### 信鸽飞行

- Herald 完成后，卷轴变形为像素信鸽
- 信鸽向右上角窗户飞去
- 飞行路径带星光尾迹粒子
- 从窗户飞出画面消失

### 粒子效果清单

- Scout：扫描线光粒子
- Scribe：墨水飞溅
- Seer：数据符号 + 光粒子
- Smith：火花飞溅
- Herald：音符粒子
- 信鸽：星光尾迹
- 失败：红色碎片

## 管理员交互

### 权限

- 复用现有认证系统，`role === 'admin'` 判断
- 非管理员：纯观看模式，所有操作按钮隐藏
- 管理员：像素风格操作按钮悬浮在 Canvas 上方

### 操作列表

| 操作 | 触发方式 | 视觉效果 |
|------|---------|---------|
| 开新流水线 | 点击"+ 新线"按钮 | 房间动画展开新流水线，角色就位 |
| 关闭流水线 | 点击线旁"×"（仅空闲线可关） | 角色走开，流水线收起 |
| 选新闻上线 | 点击收件篮 → 弹出列表 → 选择 | 卷轴从篮中弹出飞向空闲线起点 |
| 重试失败 | 点击失败工位 | 角色重新振作，重新处理 |
| 跳过步骤 | 右键/长按失败工位 → 跳过 | 卷轴直接滑向下一工位 |

### 收件篮弹窗

- 像素风格弹窗覆盖层
- 显示 pending 新闻列表：标题、来源、评分
- 按评分降序排列
- 点击选中 → 自动分配到第一条空闲流水线

## 技术架构

### 分层

```
┌─ React 层 (UI 覆盖) ──────────────────┐
│  管理员控制面板 / 统计数字 / 提示文字   │
├─ PixiJS Canvas 层 ─────────────────────┤
│  编辑室场景 / 角色动画 / 粒子效果       │
├─ 数据层 ──────────────────────────────┤
│  API 轮询 → Zustand store → 驱动场景   │
└────────────────────────────────────────┘
```

### 技术选型

| 层面 | 技术 |
|------|------|
| 渲染 | PixiJS 8 + `@pixi/react` |
| 状态管理 | Zustand（API 数据 + 场景状态解耦） |
| Sprite 资源 | 像素画 sprite sheet（PNG + JSON） |
| 粒子 | `@barvian/particle-emitter`（PixiJS 8 兼容） |
| 管理员 UI | React 组件浮在 Canvas 上方 |
| 认证 | 现有 session 系统 |

### 数据流

1. API 每 10s 轮询 `/api/pipeline` 获取最新状态
2. Zustand store diff 新旧状态，产出事件（新文章进入、角色开始工作、完成等）
3. 场景管理器消费事件，触发对应动画序列
4. 管理员操作通过 API 发送，响应后更新 store

### 文件结构

```
web/app/pipeline/
├── page.tsx                  # 页面入口，加载 Canvas + React UI
├── components/
│   ├── NewsroomCanvas.tsx    # PixiJS 场景容器
│   ├── AdminPanel.tsx        # 管理员浮层控制面板
│   └── InboxOverlay.tsx      # 收件篮展开列表
├── engine/
│   ├── NewsroomScene.ts      # 场景布局与生命周期
│   ├── PipelineLane.ts       # 单条流水线逻辑

│   ├── NewsScroll.ts         # 新闻卷轴物件

│   └── particles/            # 各角色粒子配置
├── store/

```

## 响应式与边界情况

### 响应式

- Canvas 设计尺寸 1200x700，等比缩放到屏幕宽度
- 移动端管理员面板改为底部抽屉
- 最小宽度 375px，低于此提示"请横屏查看"

### 边界情况

| 场景 | 处理 |
|------|------|
| 3 条线都满 | 提示"所有流水线繁忙"，按钮禁用 |
| 处理中关闭线 | 不允许，按钮禁用 + tooltip |
| API 断连 | 保持最后状态，顶部"RADAR LOST"告警条，自动重试 |
| 无 pending 新闻 | 收件篮空状态，角色 idle 待机 |
| 多管理员并发操作 | 乐观更新 + 冲突回滚 + toast 提示 |

### 性能

- Sprite sheet 预加载
- 单工位粒子上限 30
- 非活跃流水线降帧渲染
- `visibilitychange` 时暂停渲染循环
