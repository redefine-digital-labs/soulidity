# CryptoOpenClaw 产品开发需求文档 (PRD)

**版本**: v1.0
**日期**: 2026-03-05
**状态**: 待评审

---

## 一、产品定位

**一句话定位**：以加密新闻媒体为入口，以 OpenClaw 养成生态为核心，集 AI Agent 新闻生产、应用方向检索、养成社区、交易市场于一体的平台。

**两阶段战略**：

| 阶段 | 目标 | 核心模块 |
|------|------|----------|
| Phase 1 | 对外获客 | 新闻媒体 + AI 多角色可视化 + 养成方向检索 |
| Phase 2 | 生态深耕 | 养成社区 + 交易市场（本体+服务） |

**整体架构**：

```
┌─────────────────────────────────────────────────┐
│                   Web 前端                       │
│  新闻首页 │ Agent工作台 │ 方向检索 │ 社区 │ 市场  │
└──────────────────┬──────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────┐
│                   API 层                         │
│  新闻API │ Agent API │ 检索API │ 社区API │ 交易API │
└──────────────────┬──────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────┐
│              数据层 (Supabase/PostgreSQL)         │
│  Articles │ Agents │ Categories │ Users │ Orders  │
└──────────────────┬──────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────┐
│           后端引擎 (现有 Pipeline 扩展)            │
│  采集 → AI Agent 多角色处理 → 审核 → 分发          │
└─────────────────────────────────────────────────┘
```

## 二、模块一 — 新闻媒体 + AI 多角色接管流程

### 核心概念

现有 pipeline 是单一 LLM 处理全部流程。升级为多个 AI Agent 角色，各自负责新闻生产的不同环节，用户可以看到每个角色的工作过程。

### AI Agent 角色定义

| 角色 | 职责 | 输入 → 输出 |
|------|------|------------|
| 🕵️ 侦察员 Scout | 源头采集、去重、评分 | RSS/API → 评分后的素材 |
| 📝 记者 Reporter | 摘要撰写、翻译 | 素材 → 中英文摘要 |
| 🔍 分析师 Analyst | 深度解读、关联分析 | 摘要 → 行业分析 + 标签 |
| ✅ 编辑 Editor | 质量审核、终稿把关 | 分析稿 → 发布稿 |
| 📢 发行员 Publisher | 多渠道分发 | 发布稿 → TG/Web/Twitter |

### 可视化工作台

用户可以在 Web 端看到一条新闻从采集到发布的完整流水线，每个 Agent 角色的处理状态实时可见：

```
素材进入 → [Scout 评分中...] → [Reporter 撰稿中...] → [Analyst 分析中...] → [Editor 审核中...] → [已发布 ✓]
```

每个节点可展开查看该 Agent 的具体输出。

### 用户故事

- 作为访客，我打开新闻首页可以看到最新的加密新闻列表
- 作为用户，我可以点进"Agent 工作台"查看新闻生产流水线的实时状态
- 作为用户，我可以查看某条新闻经过了哪些 Agent 角色的处理及其各自输出

## 三、模块二 — 养成方向检索（类 DeFiLlama）

### 核心概念

OpenClaw 可以被用于各种场景（种番茄、养鱼、新闻媒体、交易分析等）。这个模块把所有养成方向分门别类，提供类似 DeFiLlama 的多维数据检索和排行。

### 分类体系

| 一级分类 | 示例二级分类 | 追踪指标 |
|---------|------------|---------|
| 🌱 农业养殖 | 种番茄、养鱼、种植规划 | 使用人数、成功率、评分 |
| 📰 内容媒体 | 新闻生产、自媒体、翻译 | 产出量、质量评分、订阅数 |
| 💹 交易金融 | 行情分析、策略回测、风控 | 收益率、使用人数、准确率 |
| 🎮 游戏娱乐 | NPC 对话、剧情生成、攻略 | 活跃度、好评率 |
| 🔧 开发工具 | 代码审查、文档生成、调试 | 使用频次、效率提升 |
| 📚 教育学习 | 语言学习、知识问答、辅导 | 学习时长、完成率 |

### 页面结构

- **总览页**：各方向的汇总数据卡片 + 排行榜（热门/新增/增长最快）
- **分类列表页**：某个方向下所有具体应用，支持排序和筛选
- **详情页**：单个养成方向的详细介绍、数据趋势图、相关 Agent、用户评价

### 用户故事

- 作为访客，我可以浏览所有 OpenClaw 养成方向，按热度/分类筛选
- 作为用户，我可以查看某个方向的详细数据和趋势
- 作为用户，我可以提交新的养成方向供平台收录

### 数据来源

初期由运营团队手动录入分类和方向数据，后期开放用户提交 + 审核机制。

## 四、模块三 — 养成社区

### 核心概念

基于现有 TG 社群验证机制（已有 Member + InviteCode 模型），扩展为 Web 端养成社区。用户围绕自己的 OpenClaw 养成方向交流、分享经验、协作。

### 社区功能

| 功能 | 描述 |
|------|------|
| 养成日志 | 用户发布自己的 OpenClaw 养成过程和心得，带方向标签 |
| 方向讨论组 | 按养成方向自动聚合的讨论区（种番茄组、新闻媒体组等） |
| 成就体系 | 养成里程碑徽章（首次养成、连续30天、达人认证等） |
| 排行榜 | 养成活跃度、贡献度、互助次数排行 |
| 互助问答 | 用户提问，同方向的养成者回答 |

### 用户等级（沿用现有 Member.level）

| 等级 | 名称 | 条件 |
|------|------|------|
| Lv.1 | 🥚 孵化中 | 注册完成 |
| Lv.2 | 🦐 初蜕壳 | 首个养成方向启动 |
| Lv.3 | 🦞 成长期 | 3+ 养成日志、参与讨论 |
| Lv.4 | 🦞🦞 达人 | 某方向被评为优质、帮助他人 |
| Lv.5 | 🦞🦞🦞 导师 | 社区贡献突出、多方向经验 |

### 用户故事

- 作为用户，我可以发布养成日志记录我的 OpenClaw 使用过程
- 作为用户，我可以加入感兴趣的方向讨论组，和同好交流
- 作为用户，我可以通过养成和互助提升等级、获得成就徽章
- 作为访客，我可以浏览社区内容，被吸引后注册加入

### 与 TG 社群的关系

Web 社区为主阵地，TG 群作为即时通知和轻量讨论的补充渠道，两端用户数据互通（通过 Member.tgId 关联）。

## 五、模块四 — 交易市场

### 核心概念

两类交易并存：OpenClaw 本体买卖 + 养成服务交易。类似于既能买卖宠物，也能雇佣别人的宠物干活。

### A. 本体交易

| 要素 | 描述 |
|------|------|
| 交易对象 | OpenClaw Agent（含养成数据、等级、技能） |
| 定价方式 | 卖家自主定价 |
| 交易媒介 | 链上转移（如 Sui NFT）或平台托管 |
| 展示信息 | 养成方向、等级、技能列表、历史表现数据 |

### B. 服务交易

| 要素 | 描述 |
|------|------|
| 交易对象 | OpenClaw 提供的具体服务（如"帮你写一周新闻分析"） |
| 定价方式 | 按次/按时间段/订阅制 |
| 服务类别 | 跟随养成方向分类（内容生产、数据分析、农业规划等） |
| 交付流程 | 下单 → 服务方 OpenClaw 执行 → 交付 → 买家确认 → 结算 |

### 页面结构

- **市场首页**：热门本体 + 热门服务 + 分类导航
- **本体列表**：筛选（方向/等级/价格）、排序、搜索
- **服务列表**：按方向分类、评分排序、价格筛选
- **详情页**：OpenClaw 或服务的完整信息 + 评价 + 购买/下单
- **我的交易**：发布管理、订单管理、收入统计

### 用户故事

- 作为卖家，我可以挂售自己的 OpenClaw 或发布服务
- 作为买家，我可以按方向/价格检索并购买 OpenClaw 或服务
- 作为买家，我可以查看卖家评价和 OpenClaw 的历史表现数据后再决定购买
- 作为用户，我可以在"我的交易"管理所有订单和收入

### 信任机制

- 交易评价系统（买家评分 + 文字评价）
- 服务交易支持平台托管担保（确认交付后放款）
- OpenClaw 链上数据可验证（等级/技能不可伪造）

## 六、数据模型扩展

基于现有 Prisma schema，新增以下核心模型。不涉及破坏性改动，全部为新增。

### 现有保留

`RawItem`, `Article`, `Company`, `ArticleCompany`, `Publication`, `Member`, `InviteCode`

### 新增模型

```
AgentRole          — AI Agent 角色定义（Scout/Reporter/Analyst/Editor/Publisher）
AgentProcessLog    — 每条新闻经过每个 Agent 角色的处理记录和输出

Category           — 养成方向一级分类（农业、媒体、金融...）
Direction          — 具体养成方向（种番茄、养鱼...），属于某 Category
DirectionStat      — 方向统计数据（使用人数、评分等），支撑检索排行

Post               — 社区养成日志
Comment            — 日志评论
Achievement        — 成就徽章定义
MemberAchievement  — 用户获得的成就

Listing            — 交易挂单（本体或服务）
Order              — 交易订单
Review             — 交易评价
```

### 关键关联

```
Member  1:N  Post（发养成日志）
Member  1:N  Listing（挂售）
Member  1:N  Order（买卖双方）
Direction  1:N  Post（日志归属方向）
Direction  1:N  Listing（挂单归属方向）
Article  1:N  AgentProcessLog（新闻处理记录）
AgentRole  1:N  AgentProcessLog（哪个角色处理的）
Category  1:N  Direction（分类包含方向）
```

### 现有模型调整

- `Member` 新增字段：`avatar`, `bio`, `exp`（经验值）
- `Article` 新增字段：`pipelineStatus`（流水线当前阶段）

## 七、页面清单与路由

### Phase 1 页面（对外获客）

| 页面 | 路由 | 功能 | 优先级 |
|------|------|------|--------|
| 新闻首页 | `/` | 最新新闻列表、标签筛选、搜索 | P0 |
| 新闻详情 | `/news/[id]` | 全文 + 各 Agent 角色处理过程展示 | P0 |
| Agent 工作台 | `/pipeline` | 实时流水线可视化，各角色状态 | P0 |
| 方向总览 | `/directions` | 养成方向分类卡片 + 排行榜 | P1 |
| 方向分类页 | `/directions/[category]` | 某分类下方向列表，排序筛选 | P1 |
| 方向详情 | `/directions/[category]/[slug]` | 单个方向数据、趋势图、介绍 | P1 |
| 注册/登录 | `/login` | 钱包连接 + TG 绑定（沿用现有） | P0 |

| 页面 | 路由 | 功能 | 优先级 |
|------|------|------|--------|
| 社区首页 | `/community` | 热门日志、方向讨论组入口 | P2 |
| 发布日志 | `/community/new` | 编辑器，选择方向标签 | P2 |
| 日志详情 | `/community/[id]` | 日志内容 + 评论 | P2 |

| 本体列表 | `/market/claw` | 筛选、排序、搜索 | P3 |
| 服务列表 | `/market/services` | 按方向分类、评分排序 | P3 |
| 交易详情 | `/market/[id]` | 详细信息 + 评价 + 购买 | P3 |
| 我的交易 | `/market/my` | 订单管理、挂单管理、收入 | P3 |

## 十、风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| OpenClaw 链上协议未定义 | 本体交易、链上验证无法实现 | Phase 2b 启动前需确认链上方案 |
| 多角色 LLM 调用成本 | 5个角色处理一条新闻，API 费用 ×5 | 非核心角色可合并、低优先级内容跳过分析师 |
| 养成方向冷启动 | 初期无用户数据，排行榜空 | 运营预填 20-30 个方向 + 示例数据 |
| 服务交易纠纷 | 买卖双方对交付质量有争议 | 平台托管 + 人工仲裁机制 |
