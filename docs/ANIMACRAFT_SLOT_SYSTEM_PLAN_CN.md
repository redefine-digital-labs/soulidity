本方案形成可实施的目标定义，未改变合约、生产配置、已有作品或进行中的交付队列。新增设计与已确认规则在下文分别标明；原 M1–M4、S0–S14 与 G1–G5 仍是项目执行依据。完整卡槽版的新增能力不能冒称原交付已经要求或已经完成。

## 2 将公开 收费 卡槽和保护分开表达

“公开 Maker”首先说明可被发现。它可能免费进入，也可能需要付费；免费进入的 Maker 也可能按完成收费。Item 的 PUBLIC／PRIVATE 状态、素材是否加密与 Maker 是否公开展示同样不能互相推导。

| 维度 | 保留或建议的表达 | 不能推导的结论 |
| --- | --- | --- |
| 发现与生命周期 | 公开发现、当前发布状态、ACTIVE／PAUSED／ARCHIVED | 公开不等于免费，不等于开放素材 |
| Maker 进入资格 | 免费／一次付费；准确版本和现有凭证 | 购买进入资格不等于每次 Complete 免费 |
| Pack 进入资格 | 免费／一次付费／INCLUDED_WITH_MAKER | 包含式资格不等于赠送独立 Item，也不自动包含未来版本 |
| Complete 政策 | 免费不限次、免费额度后付费、每次付费、免费额度后禁止；另校验总量上限 | 库存数量、槽位数量不是完成额度 |
| Maker 组合模式 | FIXED／COMPOSABLE | 创作时可以换 Item，不代表生成后能持续换装 |
| Part 装备属性 | FIXED／SLOT；Player 容量；Soul 单件布局 | 固定部位不应自动开放外部装备 |
| 第三方准入 | DISABLED／CERTIFIED／OPEN，并保留当前准入记录检查 | OPEN 表示允许未经背书的来源，不表示免校验、免资格或免准入 |
| 内容与资产 | Base／Pack／External；资格使用／独立实例；保护状态和许可 | 可见缩略图不授予源素材读取、独立转售或跨 Maker 使用权 |

作者端可以显示“固定作品”“仅本作品及已准入扩展”“允许认证组件”“允许开放组件”等可理解摘要，但摘要必须由真实配置生成，不能合并或重写底层权限维度。

## 3 统一身份与最小数据模型

保留 Maker → Part → Item → Style 的作者结构，Runtime 的精确选择与实例锁继续承担执行。新增概念首先定义为协议语义，实施时优先复用已有对象和承诺，避免为每个概念新建共享对象。

| 概念 | 必须绑定的信息 | 现有基础及变化 |
| --- | --- | --- |
| 内容来源 SourceRef | 链、Maker Root、发布版本与内容承诺；Pack 来源另带 Release 及定义承诺 | 复用现有 Base／Pack 精确绑定 |
| 部位身份 PartRef | 定义来源 ID、定义承诺、partKey | 复用 DefinitionSlot 的来源命名空间；显示名称和数组位置都不是身份 |
| 卡槽配置 SlotProfile | 固定／可装备、允许来源、Player 容量、Soul 容量 1、显示规则、适配配置承诺 | 复用 PartProfile，明确两个场景的容量 |
| 组件定义 ComponentDefinition | 产品身份、作者、来源与权利、版本、供应／发行政策、内容承诺 | Base／Pack 内容继续使用原身份；独立产品逐步解除单一目标耦合 |
| 适配声明 CompatibilityBinding | 精确产品版本、目标 PartRef、目标 Maker／Pack 版本、表现引用、所需资格、准入证据 | 新增一产品多目标声明，不放宽已有精确检查 |
| 表现定义 Representation | 媒体类型、原始素材哈希、画布、锚点、变换、轨道、颜色、遮挡规则、渲染器版本 | 普通 Style 保持一张 PNG；高级多层表现作为显式扩展 |
| 使用资格 Entitlement | 主体、来源、范围、有效条件与链上证据 | 复用 MakerAccessPass、PackPass、组件所有权和适用授权；不能由前端布尔值赋权 |
| 当前装备 EquipmentState | Soul ID、所有权轮次、revision、精确 PartRef、选择／实例／表现引用、显式空位 | 复用持久装备、CAS 和事务级更新守卫 |
| 完成及展示快照 | 原配方、真实贡献来源、价格和权利快照、输出哈希；当前展示另绑定装备 revision | 原作品记录与当前穿戴保持独立 |

同名 Part 可以分别来自 Base 和两个 Pack，它们仍是三个不同部位。更新、重新排序、空槽、Pack 添加均不能改变已经分配的身份；切换 Pack 版本需要明确映射，不能按名称猜测。

独立组件实例只产生一次所有权。一件组件有三份适配声明，不等于用户得到三件组件。实例锁以实例身份为准，在所有目标间保持唯一占用；获得额外副本必须经过该产品的正常发行政策。

## 4 公开与付费内容的资格矩阵

下表中的“使用”均包含目标兼容、有效来源、正确版本和适用许可；付费与免费只影响资格取得方式。公开预览只展示作者已允许公开的内容。

| 来源组合 | Player 使用前 | 新建 Soul 的 Complete | 持久装备与转售 |
| --- | --- | --- | --- |
| 免费进入 Maker 的 Base | 按现有流程验证或取得免费资格 | 执行 Maker 自身完成政策，不能假定免费 | 可装备部位按配置使用；未资产化内容不能独售 |
| 付费进入 Maker 的 Base | 核实已有资格；没有才购买 | 进入费和完成费分别计算 | 已有效取得的资格不重复买；转让 Soul 不自动转让购买者的 MakerPass |
| 任意 Maker＋免费 Pack | 目标 Maker 资格＋免费 Pack 资格 | 按实际使用的该 Pack 执行完成政策 | 免费 Pack 不自动开放全部素材或独立转售 |
| 任意 Maker＋付费 Pack | 目标 Maker 资格＋准确 PackPass | 同一 Release 的多个选中 Style 按既有 Pack 规则去重结算 | 不因用户买了 Maker 就绕过 Pack；已有 Pass 不重复买 |
| Maker＋包含式 Pack | 验证包含关系及 Maker 资格，按现有路径建立所需凭证 | Pack 的完成政策仍独立生效 | 只包含真实授权的范围；管理权转让不凭空抹除已发资格 |
| 已持有独立 Base／External Item | 核实实例所有权、锁及有效适配 | 保留已适用的完成贡献与权利校验；不能自行新增组件使用费 | 可转让实例按其政策独售；装备时锁定，卸下后可重新使用 |
| 外部组件装入 Pack 新增部位 | 目标 Maker 资格＋该 Pack 结构资格＋组件实例／使用资格 | 结构依赖与计费贡献分别核算 | 持有组件不能绕过付费 Pack 的部位使用权 |
| 外部组件使用另一 Pack 的素材表现 | 除目标资格外，必须证明素材使用许可和对应来源资格，或已有明确独立发行授权 | 经认证的真实素材贡献不能改标 External 来逃避原政策 | 使用声明不能扩大原 Pack 授权，不能公开其受保护素材 |

如果组件已经通过有权主体明确取得独立发行和使用授权，使用它不应自动要求购买整套来源 Pack。该范围必须写入可验证的发行／授权记录；缺失时按有依赖的内容处理。适配者自报“已授权”不足以解除来源资格。这一独立授权表达属于新增设计。

### 4.1 四种费用分别处理

1. Maker／Pack 进入费用：获得内容选择与适用编辑资格，已有有效资格不重复收取。
2. 独立组件取得费用：领取或购买组件实例，不能与 PackPass 混成一种资产。
3. Complete 费用：创建新 Soul／相应输出时，执行 Maker 和实际使用 Pack 的完成政策、次数与上限。
4. 二级交易费用：遵循实际出售资产的市场政策；装备独售沿用 2.5%，其他资产沿用其当前政策。

持久换装不创建新 Soul，默认不重复收取 Complete 费用或扣除完成次数，也不新增换装费。它仍校验访问资格、组件所有权与当前可用政策。额度耗尽阻止新的 Complete，不能被实现为没收独立组件或禁止安全卸装。以后若需要按换装计费，应作为新的商业产品决策单独定义。

### 4.2 真实使用与报价

将依赖区分为“校验／结构依赖”与“计费贡献”。仅打开 Pack 面板、启用其展示开关、挂接一个空定义，不能自动把 Pack 加入完成收费清单。现有 Pack Style 选择继续使用当前 usedPacks 规则；新增适配表现引用付费 Pack 素材时，需要在适配发布时确定可验证的来源贡献。

同一 Release 的多项 Style 按现有计费单位去重，不能因同一来源在多个读取路径出现而重复扣费。不同版本不能仅凭同一 semanticPackId 合并；选择冲突版本必须解释并拒绝，而非双收费用。声明的依赖集合有数量上限、精确版本并禁止循环。

交易前输出明确的业务分项：尚缺的进入费用、组件取得费用、Base 完成费用、各真实使用 Pack 的完成费用和适用平台费用。协议分成如果已经包含在某笔价格中，不能再次叠加。所有金额按链上币种及整数最小单位计算；Gas 和 Walrus 成本另列，不能伪装成已确定的业务总价。

示例仅说明规则：用户已买 Maker 和 Pack B，另有随 Maker 包含的 Pack A。本次 Base 完成费 4、A 完成费 2、B 完成费 1，B 使用两张 Style；已开启但未使用的 Pack C 完成费 9。本次内容费用为 7，而非再加进入费、重复计算 B 或收取 C。适用固定协议费用另列。示例不代表现行价格。

Complete 的额度校验、业务结算和最终发行应保持同一原子业务边界。内容上传及独立取得资格可能已在先前交易完成，不能承诺后续取消会撤销这些已完成交易；未知结果先查原交易，再恢复，不能重新创建付费尝试。

## 5 Expansion Pack 的部位与适配规则

Pack 保持现有两种贡献：向母 Maker 已有部位增加内容，或增加 Pack 自有部位及相关轨道、颜色与规则。父定义只读，包自有定义使用独立命名空间。

| 情况 | 目标规则 |
| --- | --- |
| 为 Base 部位添加 Item／Style | 使用父 PartRef，遵守父部位容量与策略，不改写父部位身份 |
| 新增 Pack 自有部位 | 使用 Release＋partKey 的身份；Player 容量取作者值，Soul 为一件 |
| 多个 Pack 同名新增部位 | 明确显示来源，独立处理，不能碰撞或覆盖 |
| Pack 提供颜色／轨道／Rules | 精确绑定来源；不能回退到母 Maker 的同名字段 |
| 关闭 Player 中某 Pack | 复用原选择移除及合法默认处理；不删除购买凭证、不发起隐含交易；再次验证配方 |
| 卸下 Soul 的 Pack 组件 | 留空，不能套用 Player 的默认恢复行为 |
| 移除已有装备的 Pack 定义 | 同一更新先处理全部受影响装备与锁，不能留下悬空引用；正常操作不可用时仍提供有界安全移除 |
| 外部组件进入 Pack 新增部位 | 新增适配必须同时满足 Maker 的准入上限、该 Pack 的目标许可及用户资格 |

现有 Maker 准入权威继续作为有效入口。需要允许 Pack 作者管理自己新增部位时，应由 Maker 授予范围受限的能力，只能管理该 Release 命名空间，不能扩大 Maker 上限或修改 Base。该委托是可选扩展，不是现有 Pack 发布的新前置条件，也不新增平台签名。

对已发布 Pack，未声明对外开放的部位保持原权限。购买 Pack、作者身份、素材持有和准入管理权是不同权限，不能互相代替。

## 6 跨 Maker 的产品与适配分离

完整卡槽版纳入一个有界目标：同一独立组件可提供两份以上明确适配，在不同 Maker 的合法目标中使用。现有单 Maker 组件可视作只有一份精确适配的情形，不强制重新发行、购买或修改内容。

适配发布至少完成四项验证：

1. 来源侧证明组件和表现的作者／发行权限、权利范围与真实素材贡献。
2. 目标侧证明 Maker Root、版本、PartRef、目标 Pack 与准入记录，不能只提交通用的 head／body 标签。
3. 技术侧验证表现素材哈希、坐标／锚点／轨道／配色、渲染版本及资源预算。
4. 使用侧在每次装备时验证当前持有人、所需 Maker／Pack 资格、实例锁和状态 revision。

`head`、`left-hand` 等语义标签只用于检索推荐，适配分组只减少重复配置，二者均不授予装备权限。同一兼容族的新版本也必须产生精确的新绑定；不允许通配版本自动扩大到未知内容。

每个适配版本不可变。作者可提议新表现，持有人明确选用后才改变当前装备；已接受的旧版本不会被后台 URI 替换。组件实例保持原 ID 和发行数量，改变适配不铸造副本。该机制借鉴 ERC-5773 的资源接受模型，但使用 Sui 对象与既有权限执行，不宣称 ERC 接口兼容。

## 7 表现 渲染与原作品保真

原作品记录保存 Complete 时的完整配方、输出、来源和权利快照。当前穿戴保存 Soul 装备状态。Showcase 必须明确使用对应状态；不能把原成品 PNG 当成包含可卸装备的底图，再叠加新装备。

普通 Style 继续严格对应一张 PNG 和原编辑参数。高级组件可以有一份表现引用多个已认证渲染层，例如外套前片与后片；它仍占一个装备位。高级表现不得暗中转换已有 Style 语义，且必须校验所有层的来源、保护状态和许可。

表现契约至少包含画布坐标系、锚点、局部变换、层排序、同层稳定排序、遮挡／蒙版、颜色通道、媒体类型、原始内容哈希和渲染器版本。先完整实现现有二维能力；骨骼、动画和三维仅保留可扩展类型，实际支持以适配器和验收为准。

特别处理 Player 多容量与 Soul 单件的边界：原 Complete 配方必须完整保留，不能为了单件装备而静默丢掉选项或铸造一个假 Item。现有空装备初始化路径保持可用；首次进入持久衣柜时展示其实际状态，用户明确选择每个部位的当前一件。原多选作品保留在原作品入口。若未来要求“原多选外观一键成为一个装备”，需要单独定义不可交易的外观组合或可发行组件，不能在本次实施中隐式合并。

当前外观进入装备模式后，“未装过”“已明确卸下”“读取失败”必须可区分。空位就是空位；读取失败展示不可用状态；关闭空装备绑定、上架或转手不能被解释成重新穿上原成品图中的服饰。若当前状态没有足够信息表达这些差异，补充最小明确状态并联动全部读取器，不能靠前端猜测。

Maker／Pack 的创作完成规则仅在对应场景执行。持久衣柜允许稀疏与空位，按已确认规则执行可见性与安全校验；不能因创作时 required 或 Complete-only 组合规则而阻止卸装。表现不能改变游戏数值或取得额外执行权限。

## 8 统一操作与读取接口

下列名称是语义接口，不是已存在的 ABI。实现应封装现有权威读取与交易构造器，避免并行维护第二套状态。

| 接口能力 | 结果及要求 |
| --- | --- |
| 读取可用部位 | 返回有来源的 PartRef、配置、版本与权限摘要，包含空位 |
| 查询可用组件 | 分页读取真实资格／库存和已准入适配，区分未加载、空集合、失败与不完整结果 |
| 解释能否装备 | 返回明确原因：缺 Maker／Pack 资格、未准入、错版本、固定部位、实例已锁、目标冲突、素材不可用等 |
| 读取当前组合 | 返回 Soul／owner epoch／装备 revision／选择／来源／适配版本及内容承诺 |
| 解析渲染清单 | 返回同一快照的图层计划与授权后的素材引用；公开描述和受保护读取分开 |
| 准备换装／应用搭配 | 生成具体差异、需要移除的旧实例、资格和交易内容；不自动购买缺失资产 |
| 执行与恢复 | 在现有事务更新守卫内移除、选择、装备、最终验证；按原交易记录查证未知结果 |

单件替换与多部位换装使用同一更新流程：取得精确快照 → 校验全部候选与资格 → 构造事务 → 链上重新校验 → 原子更新全部锁及选择 → 最终读回。任何步骤失败保持原状态，不能先解除旧锁、再让后续装备失败成为永久半完成。

一件实例由 Player 临时 Loadout 占用时，向 Soul 装备的转接必须释放旧锁再建立新锁，能原子组合的就在同一事务完成。不能通过复制快照绕过占用；Complete 记录中出现组件，不代表另发了一件或已经形成持久装备。

命名 Loadouts 保存配置而非资产：应用时重新检查最新所有权、资格、版本及锁，失效项明确显示，不能自动购买、自动替换或静默跳过。私密名称与保存内容继续按 owner epoch 加密；已经上链的当前装备关系不能被称为私密。转手后旧私密资料不自动交给新主人。

### 8.1 Sui 实现与资源边界

新增能力优先沿用现有对象归属和访问控制。不可变定义与表现通过内容承诺引用，持有实例继续使用现有所有权及唯一锁，动态选择写入对应 Loadout／Soul 装备状态。发布和准入管理保留其权威对象；避免让每次换装都额外写入同一个全局注册表。实施时以真实事务的对象读写集合和并发结果验证，不能仅凭 Sui 对象模型推断性能。

统一 SDK 可以使用现有 RPC、索引服务和客户端缓存定位候选，但候选列表不授予权限。执行前必须读取权威对象并由合约再验证。缓存至少区分来源版本／承诺、所有权轮次、装备 revision 和准入／生命周期变化；缓存中的“可装备”和旧价格均不能成为签名时的最终依据。

完整版本必须给出并验证每次事务的部位数、依赖数、对象数、渲染层数、素材尺寸／解码量和请求预算；数值由当前实现限制与实测确定。钱包库存分页独立于装备容量，不能用槽位上限截断用户库存。超出一次原子换装预算时，应在签名前明确拒绝或让用户重新选择范围；不能静默拆成多笔交易后仍声称全部成功或全部回滚。验收报告记录单件替换、多件搭配、带付费 Pack 的 Complete 以及最大允许布局的 Gas、耗时与失败恢复结果。

## 9 内容保护 权利与生命周期

公开介绍、公开展示图、可编辑源素材、受保护组件、命名搭配分别处理。付费标志不自动决定是否加密；保留作者既有保护配置，不能因优化存储或读取而自动公开素材。

Walrus Blob／Quilt 的存储地址与原始内容身份分开。素材必须同时绑定原始哈希、存储引用、认证结果和必要的解密证明。受保护引用换成 Quilt patch 后，Maker、Pack、External、Player、SO 和 Seal 授权路径必须一致核验；批次在签名前固定成员、排序和原哈希，已签结果的恢复不得因后续编辑重建另一个付费批次。

许可沿用现有来源声明和快照。新适配不能扩大商用、改作、源素材访问、独立发行或跨应用范围。混合来源产生冲突时，明确显示冲突来源并阻止相应发行／使用，不能用一个“已拥有”标志覆盖。技术验证证明绑定与权限，不自动证明作品原创性或法律权属。

| 事件 | 新选择／新 Complete | 当前与历史展示 | 卸装与交易 |
| --- | --- | --- | --- |
| Maker／Pack 正常有效 | 按资格、配方、额度及价格执行 | 当前组合与原作品分别可验证 | 依现有政策 |
| 进入资格已购买 | 不重复收取同一有效资格费用 | 只授予其明确范围 | 不自动获得内容独立转售权 |
| 完成额度耗尽 | 依政策付费或拒绝新 Complete | 不仅因额度耗尽抹除已有记录 | 不阻止安全卸装，不凭空扣换装次数 |
| 暂停／归档／撤销准入 | 遵循已发布策略拒绝相应新操作 | 已完成输出按原记录权限；原素材是否可读按原有效政策，不许无条件承诺永久解密 | 必须保留所有者安全解除选择／实例锁路径 |
| 新内容／适配版本 | 重新建立精确绑定与资格，不能静默切换 | 历史快照不变；用户选用后才更新当前穿戴 | 沿用实例及其真实所有权 |
| Maker／Pack 管理权转让 | 新操作核对当前管理权 | 已发资格不能仅因控制 epoch 改变而失效 | 收益与管理权按原政策交接 |
| Soul 上架／出售 | 托管期间不能继续换装 | 市场显示实际出售状态和原作品记录的区别 | 原子卸装留卖家；买家不获卖家的 PackPass、组件或私密搭配 |
| 组件独售 | 已装备时必须先按规则解除锁 | 原 Soul 对该槽位的当前展示随真实状态更新 | 只转让所选实例，2.5% 平台费，旧 owner 失去实例使用权 |

对已有版本，严格按其链上政策和凭证核实生命周期含义；本表不能追溯改变已购买权利。对新版本，发布时把暂停、撤销、升级和展示范围写明，避免由 UI 临时解释。

## 10 兼容已有 Maker 和 Pack 的验收边界

本轮“兼容已有”包括功能、内容与权利三个层次。固定 Maker 不必启用卡槽；可组合 Maker 保留原 Part、容量、准入与素材；付费及包含式 Pack 保留已确认的收费与授权语义。

在实施切换前，建立有界兼容清单：保存的 Maker／Pack 文档、原素材哈希、Root／Release 及版本、准入记录、Pass、独立实例、已完成 Soul、私密搭配与未完成交易。已有线上资产与凭证需以实际链上清单核对；某次 Plaza 显示零个 Maker 不能作为“没有资产，可清空”的证明。

| 兼容对象 | 必须保留或验证 |
| --- | --- |
| 固定免费与付费 Maker | 创作和完成照常；不自动生成衣柜，不要求改作品重买资格 |
| 现有可组合 Maker | 原 Player 选择、Part 容量、Rules、配色、轨道及渲染不漂移 |
| Pack 扩充 Base 内容 | 精确引用父定义，原使用资格与收费不变 |
| Pack 自有部位 | 来源隔离、定义顺序、容量与空位完整；不会覆盖同名 Base |
| 已买／包含资格 | 正确识别已取得范围；不重复购买、不把包含关系扩大到未授权版本 |
| 已有独立组件 | 实例 ID、来源、供应与锁不因新增适配而复制或被重新收费 |
| 已生成 Soul | 原配方／输出／权利可验证，当前装备与历史作品不混淆 |
| 已签待确认操作 | 按其原身份与交易恢复；新方案不能换内容重签冒充恢复 |

兼容不等于未经验证地承诺任意历史 ABI 都可运行。目标仍是一套权威实现，不堆叠旧发行器或多个可选 Runtime；实施评估若发现真实资产／凭证无法由目标实现承接，必须先完成具体承接方案与验收，再切换。不能依据旧“可全新初始化”的背景直接忽略本次保留已有内容与权益的要求，也不能未经请求执行迁移或清空。
