## Codebase Patterns
- Prisma table/bootstrap stories in this repo fit well with a small Vitest contract under `tests/new-web/` plus a hand-written SQL migration under `prisma/migrations/`.
- Local bootstrap data is usually exposed as an explicit root `npm` script that runs a `tsx scripts/*.ts` file, not through Prisma's global seed hook.
- Desktop catalog reads should start from `DesktopCatalogEntry` and then hydrate source records by `sourceRef`, because that is the repo's curated/public visibility gate for both starter and soul sources.
- Until Soul gains dedicated desktop manifest fields, the desktop detail API should synthesize soul manifests from `SoulAsset.contentBlobId` and expose the main blob as a single downloadable bundle file.
- Desktop device auth stories should keep route handlers thin and centralize lifecycle rules in `web/lib/desktop/device-session.ts`; `invalid_code` is a synthetic poll-only response, while persisted session states stay on `pending` / `confirmed` / `expired`.
- Browser-side desktop auth pages should carry only `userCode` in the URL, keep `deviceCode` server-side, and mint the final `soulidity://auth/device?...` deep link from `web/lib/desktop/device-session.ts` after confirmation.
- Account-scoped desktop profile APIs should resolve the current persona via `DesktopCatalogEntry.sourceType + sourceRef`, while `DesktopProfile` itself only stores the source pointer, `lastSyncedAt`, and preferences.
- Desktop shell stories can lock the navigation contract early with a plain `desktop/src/app/routes.ts` module plus a focused Vitest contract under `tests/desktop/`, instead of waiting for browser-only assertions.
- Tauri 2 `generate_context!()` still expects the default icon assets under `desktop/src-tauri/icons/`, so scaffold or copy the icon set before treating a new desktop shell as compile-ready.
- Frontend-facing desktop contract modules under `desktop/src/` should stay browser-safe; model app-data layout with separator-aware string helpers and leave actual filesystem access to later Tauri/Rust commands.
- Desktop auth work here should keep browser/deep-link state logic pure in `desktop/src/lib/auth.ts`, move runtime-specific I/O into `desktop/src/lib/auth-runtime.ts`, and let Tauri Rust commands own `auth_session.json` plus BFF calls to avoid desktop-web CORS issues.
