# Agent 执行规则

必读专业基线：[项目与产品工程管理手册](PRODUCT_ENGINEERING_HANDBOOK_CN.md)第1–4、9、12节及任务适用专项。原卡记录版本、适用性和证据；高风险工作使用[评审记录](templates/product-engineering-review.md)。已知版本无需每次全文重读，规范成文不代表控制已部署。

2026-10-03 用户授权启动管理工具与Agent组织。本期采用按任务执行，尚无独立常驻服务、定时调度或个人机器人账户。

1. Slack Milestones 管阶段，Delivery 管任务。本地运行记录是证据快照，不另建手工任务看板。
2. CEO选择Ready任务，检查依赖、现有执行者与源码/运行基线，再以合同和最小上下文启动有界Agent。并发最多3名执行者加CEO。
3. 单任务唯一Owner；账号、岗位ID、会话和Soul对象分开记录。未连接账号不得伪装成实际负责账号。
4. 先确认权威工作区；不能从当前旧v5目录直接实现v8功能。保护在途PR和未提交工作；并发写源码用独立工作区。
5. 当前任务允许管理文档、Slack管理清单与只读GitHub/公开产品核验。源码实施逐任务划范围；没有新增提交、推送、PR变更、部署、资金或签名授权。
6. 对外发消息需要明确发送指令；创建清单不等于向所有频道广播。敏感上下文不放公开任务/外部创作者提示词。
7. Backlog → Ready → In progress → Review → Done；依赖未满足则Backlog/Blocked并写原因。产物存在才Review，独立验收通过才Done。
8. 执行记录含任务、角色、时间、基线、动作、结果、产物、成本（未知则未知）、人工介入与验收者；不记录密钥或签名。
9. 按任务启用，空闲岗位不算正在运行；中断即可停用。C01为10月3–16日，10月10日中期评审，日期是计划，未创建提醒或自动化。
10. 内部creator-alpha不是外部采用；简报、发现、编辑、模拟、测试网、主网分别记录。内部QA不能替代外部审计。

## 敏捷与八阶段执行（2026-10-05）

执行[统一协议](OPERATING_MODEL.md#8-敏捷--devops-八阶段统一执行协议2026-10-05-用户确认)：Plan → Code → Build → Test → Release → Deploy → Operate → Monitor → Plan。
每次有界任务输入/输出均记录阶段、原卡ID、实际证据及退出条件；任务状态和阶段分开。
设计/商业/风险进入原计划，Bug回流原卡，运行与监控结果进入下一轮计划。历史行不凭状态猜阶段。
本规则只同步执行口径，现有在途Owner、Sprint、门禁和权限不变；实际源码与生产推进依原授权。

## AI/Codex协作细则 v1

执行[运行协议第9节](OPERATING_MODEL.md#9-soulidity-的-aicodex-协作方法-v12026-10-05)：原卡记录用户结果、权威基线、写入范围、验收、授权和证据；按独立性与审查容量决定并行，共享浏览器/钱包/发布目标单一持有人，最终组合候选重新验收。可复用[任务合同模板](templates/ai-work-item.json)。规则不自动启动Agent或调度，也不扩大权限。
