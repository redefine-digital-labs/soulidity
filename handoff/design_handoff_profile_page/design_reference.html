The profile page, fixed.

Walking through the live SpaceProfilePage component against the screenshot: the Trainer view has a 180px empty banner, an avatar floating in negative space (-mt-9 over a shorter-than-expected hero), and six zero-value stats for a brand-new account. First impression is "broken," not "new."

PR1

Avatar clips above the banner — banner height vs -mt-9 are mismatched

page.tsx:168–173 · hero 120/180px + avatar 72px offset -36px

Hero is h-[120px] sm:h-[180px] but the avatar uses -mt-9 (-36px) with a 3px border in --bg. On the screenshot, the avatar sits outside the hero entirely — the 72px circle is floating in the dark page surface with the banner ending cleanly above it.

FixUse a wrapper with relative and absolute-position the avatar overlapping the banner: translateY(-50%) at the banner's bottom-left. Drop -mt-9. Replace the flex items-end justify-between row with a two-column layout: avatar stays pinned, Share/Follow sit on a separate right-aligned row.
CriticalLayout
PR2

Six zero-value stats are the entire identity of a new Trainer

page.tsx:193–240 · stats row

0 Souls Created · 0 EXP · 0 Posts · 0 Followers · 0 Following · 0 Achievements. Every stat is zero — the page reads as "empty profile" instead of "new member." A first-time Trainer's public page will scare off any collector clicking through.

FixEmpty-profile variant: if souls.length === 0 && posts.length === 0 && exp === 0, collapse stats into a single "New Trainer · joined {date}" pill and show a next-step prompt (owner view: "Mint your first Soul →"; visitor view: "This trainer is just getting started."). Reveal the six-stat row only once any value is non-zero.
CriticalFirst-run
PR3

"human" tag is redundant — the page already says "Trainer · curator"

page.tsx:183 · kind tag

The hero already labels the page Trainer · curator. Next to the name we then render <Tag>{profile.kind}</Tag> which prints human. For a user whose PRD describes them as "Trainer" or "Collector," showing the raw DB enum value breaks character. And "human" next to "Level 1" reads like an RPG stat block.

FixMap kind to the UI noun: trainer → Trainer, agent → Soul. Drop the tag next to the name (hero caption already carries it). Keep Level 1 only on Soul spaces, not Trainer spaces — a human getting XP for logging in is a game mechanic that doesn't fit a "premium ownership infrastructure" positioning.

page.tsx:186–189

PR6

Share button is isolated and misplaced

page.tsx:177–181 · flex items-end justify-between

Because the avatar is on the left of the row and Share/Follow are on the right, on an empty profile Share is the only action visible and it sits alone in the middle of a long empty line. It also outranks "Follow" visually (ownership view hides Follow), even though Share is a weaker action.

FixMove Share into the account dropdown (kebab menu next to name) when viewing your own profile. Visitor view: primary = Follow, secondary = Share, both pill-styled on the same baseline as the name.

The same empty state renders whether you're viewing your own profile or someone else's. An owner sees "🫥 No Souls published yet" — which reads passive/melancholic — when the right CTA is "Mint your first Soul." And the face emoji reinforces the earlier "feels broken" impression.
